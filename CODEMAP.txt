# WorkSchedule 코드맵
# 의도 기준: APP_INTENT.md (Firebase DB 기반 웹/이미지 출력 도구)
# 기준: Firebase DB 원본 + docs 웹 출력 + 카톡 PNG 이미지 출력
# surface_type: site/static-web 또는 docs web
# Android APK/app wrapper, Gradle 빌드, ADB 설치 큐는 사용하지 않는다.

## 실행 경로
- Firebase DB SOT: `/workschedule_v2`
- 웹 출력: `docs/` 정적 파일, GitHub Pages `https://wk7007-wk.github.io/WorkSchedule/`
- 루트 `index.html`은 Pages source가 root일 때도 최신 `docs/`로 넘기는 canonical redirect다.
- 하이닉스 소비자: `/root/my-first-project/AttendanceBoard/docs/hynix/index.html` 근무표 탭
- 카톡 이미지 출력: `docs/app.js`가 최신 근무표 PNG를 만들고 웹 공유 메뉴 또는 다운로드로 넘긴다.
- 카톡 이미지 근무 확인: `docs/app.js` confirmation panel이 `/packhelper/storebot_termux/work_schedule_image_preview_queue`를 읽고, 확인 시 `/packhelper/storebot_termux/confirmed_schedule_write_requests`에 `confirmed_schedule_write_request`만 enqueue한다. 이 panel은 `/workschedule_v2` 직접 write를 하지 않는다.
- StoreBotTermux/대시보드/HynixOps는 WorkSchedule 데이터를 소비한다. 원본 저장 경계는 Firebase `/workschedule_v2`다.
- `/packhelper/storebot_summary/schedule`은 캐시/표시용이고 canonical 근무표 근거가 아니다.
- Google 연동(코어 구현/라이브 비활성): `server/calendar_sync/` 양방향 worker와 `docs/calendar_core_logic.js` outbox 계약. 하이닉스 전용 새 계정 + 별도 OAuth client/config/store만 허용하며 BankTotal 개인계정의 token/Calendar ID/syncToken 재사용 금지. Calendar는 `/workschedule_v2`의 공통 필드 projection/edit surface이고 canonical은 아니다.
- 운영메뉴얼 조회: `docs/manual_logic.js` + `docs/app.js` 운영탭. Firebase `/packhelper/ops_manual` 원본 항목은 read-only durable source로 합산하고, 사이트 입력은 후보 큐만 쓴다.
- 메모추가 통합 입력: `docs/index.html`/`docs/app.js` intake panel. 텍스트, URL, 이미지(붙여넣기/드래그/업로드), 카카오 대화, CLI, 타이머앱, 사이트 입력을 즉시 envelope로 만들고 `/packhelper/ops_manual/candidates/{id}` 후보로 enqueue한다. 실패 시 `localStorage`는 임시 보관 백업만 맡는다.
- 공통 스키마 계약: `/root/my-first-project/rules/workschedule_schema_contract.txt`

## app.js 주요 섹션
- config: `FB`, `FW`, 인증 설정, 06시 day-boundary, 날씨 기준 지역, 기본 직원 표시값
- store: `S` 단일 상태 객체. 직원, 스케줄, fixed, 휴무, 출근 기록, SSE 상태 보관
- api: `fbG`, `fbP`. Firebase RTDB `.json` GET/PUT, `READONLY` guard
- schedule delivery: 최신 근무표 변경 감지, idle/periodic due 계산, PNG 생성, 웹 공유/다운로드 출력
- auth gate: PIN + 등록 단말 또는 GPS factor. 정적 클라이언트 IP 헤더는 신뢰하지 않음. 인증 화면은 PIN/위치/단말 상태를 한글로 보여준다
- SSE: 직원/선택일 스케줄 SSE, 날짜 변경 세대관리
- fixed schedule: 날짜별 overrides 우선, clear는 fixed fallback 차단, fixed는 `/workschedule_v2/fixed_schedules` 값만 사용
- data loading: planned schedule은 employees/fixed_schedules/overrides/status, 실근태는 `/workschedule_v2/attendance`
- render: dashboard/day/people/month/timebar/list/ops 탭, 주간 개요, 날짜 스트립
- actions: shift 저장/휴무/고정값, 표준입력 live write/preview request 분기, 직원 disabled 처리, 휴무 일괄 파싱
- confirmation queue: 카톡 이미지 preview item 표시, date/employee/action/shift/off/clear 보정, confirmed request enqueue, reject/hold review metadata patch

## Firebase 경로
- `/workschedule_v2/employees/{empId}`
- `/workschedule_v2/fixed_schedules/{empId}`
- `/workschedule_v2/overrides/{yyyy-MM-dd}/{empId}`
- `/workschedule_v2/status/{yyyy-MM-dd}/{empId}`
- `/workschedule_v2/attendance/{yyyy-MM-dd}/{empId}` — 출근/퇴근/실근태 원본
- `/packhelper/ops_manual` — 읽기 전용 운영메뉴얼 source. WorkSchedule 운영탭과 HynixOps 운영메뉴얼 탭이 소비한다.
- `/packhelper/ops_manual/candidates/{id}` — 사이트 운영메뉴얼 입력 후보 큐. WorkSchedule intake panel이 `schema_version`, `source_channel=site`, `source_event_id`, actor, captured time, text/title/body/url/category hints, raw payload, classification hints, `status=pending`, `status_history`를 enqueue한다.
- `/packhelper/storebot_termux/work_schedule_image_preview_queue/{event_id}` — 카톡 이미지 근무 preview/read source. confirmation panel은 review metadata만 patch할 수 있고 schedule DB write는 하지 않는다.
- `/packhelper/storebot_termux/confirmed_schedule_write_requests/{request_id}` — confirmation panel과 표준 근무 수정 요청이 backend worker에 넘기는 confirmed request queue. 필수 payload는 `actor/source_event_id/date/employee/action/confirmed_at_ms/dry_run_result`이고 live 요청은 `dry_run=false` + `execute_live_write=true`일 때만 보낸다.

## 데이터 경계
- Firebase `/workschedule_v2`가 근무 데이터 단일 원본이다.
- `localStorage`는 인증 토큰, UI 상태, 후보 enqueue 실패 시 임시 보관 백업, 이미지 출력 due 상태 같은 브라우저 보조 상태만 보관한다.
- 운영메뉴얼 durable source path는 `/packhelper/ops_manual`이며 WorkSchedule은 원본 항목을 직접 쓰지 않고 후보 큐만 쓴다.
- 근무표 canonical 계산은 `/workschedule_v2/employees + fixed_schedules + overrides + status` 우선이며 `storebot_summary/schedule`은 표시 캐시로만 둔다.
- 직원 삭제는 노드 삭제가 아니라 `disabled:true`, `active:false` 저장이다.
- 휴무 해제/근무 clear는 삭제 대신 명시 값으로 남긴다.
- 출근/퇴근/실근태는 `/workschedule_v2/attendance`만 읽고 쓴다.
