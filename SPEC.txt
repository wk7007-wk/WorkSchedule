# WorkSchedule 상세 스펙
# 규칙(CLAUDE.md)과 분리된 상세 구현 명세
# WorkSchedule은 Android 앱이 아니라 Firebase DB 기반 웹/이미지 출력 도구다.

## 직원별 능력 (가능 역할)
| 직원 | 주방 | 차배달 | 오토바이 |
|------|:----:|:------:|:--------:|
| 이원규 | O | O | O |
| 리 | O | - | - |
| 히오 | O | - | - |
| 권연옥 | O | - | - |
| 사아야 | O | - | - |
- 수정 팝업에서 능력 밖 역할은 비활성화(취소선)

## 고정 스케줄
- 실제 직원별 시간은 Firebase `/workschedule_v2/fixed_schedules`에서 확인한다.
- 자동 적용: 날짜별 `overrides` 입력 없고 `clear/off`가 아닌 경우에만
- 기존 입력 보존: 절대 덮어쓰지 않음

## 인원 기준 프리셋 (ws_staff_settings)
| 프리셋 | 6~17시 | 피크(18~19) | 야간(20~02) |
|--------|:------:|:-----------:|:-----------:|
| 250만(기본) | min1/max1 | min3/max3 | min2/max3 |
| 300만 | min1/max2 | min4/max5 | min3/max4 |
| 350만 | min1/max2 | min4/max5 | min3/max4 |
| 맥스 | min1/max2 | min5/max6 | min4/max5 |
- 오토바이/차배달: max1/min0
- 요일별 기본: 월350, 화수목250, 금300, 토300, 일350
- 커스텀: 인원 모달에서 0.5 단위 조절 → presetOverrides

## 편입 로직
1. 전원 주방 시작 (주방 공백 불가)
2. 주방 min 충족 → 초과 인력 배달 편입
3. 편입 우선: 오토바이 > 차배달
4. 편입 후 주방 min 이하 안 내려감

## 배달대행 규칙
- 바이크만 (차 안 탐), 영업 10:00~01:00
- 부족분만: daFill = max(0, 오토바이max - 실인원)
- 01~03시 (대행 마감): 배달 합산 min1/max1

## 휴무 관리
- 등록: 개별(직원+날짜) / 일괄 텍스트 입력
- 파싱: M/D콤마, 범위(~), ISO, 요일
- 매주 반복: 리=월, 히오=월, 권연옥=수목토일, 사아야=목금토일
- 타임라인: 반투명 + 빨간 "휴무" 오버레이
- 해제: dayoffs[empId][dk] = false (delete 아님)
- generateAutoDayoffs: === undefined일 때만 생성

## UI 구조
1. 헤더: 날짜+◀▶+직원관리+휴무+확정/작업중+새로고침+월간
2. 브리핑 패널: 휴무자/주간누적/날씨/매출변동/근무현황
3. 탭: 타임바(메인) / 리스트 / 주간
4. 타임라인: 06시 day-boundary 기준 당일 근무자 첫 출근~마지막 퇴근, 직원별 근무바+역할+휴무+충돌
5. 합계행, 인원체크, 주간개요
6. 정보: 날씨+경기+물류
7. AI 스케줄링 (Gemini), 공유 (.ics 등)
8. 운영탭: 하이닉스 운영메뉴얼 조회. 검색 input, 카테고리 칩, 태그 칩, 메뉴얼 카드만 표시하고 내부 정리 알고리즘 설명은 노출하지 않음

## 수정 팝업
- 텍스트 select + 게이지형 바 (양방향 동기화)
- 빠른선택: 10-18, 10-20, 17-03, 18-03, 16-24, 풀
- 역할 선택: 능력 기반, 불가능=비활성화

## 날짜 스트립
- 하단 60일 (-7~+52) 가로 스크롤
- 확정=초록테두리, 부분=연초록+비율, 없음=회색
- 공휴일: KR_HOLIDAYS Set (2026-2027)

## localStorage 보조 키
- ws_employees, ws_sched_{yyyy-MM-dd}, ws_dayoffs
- ws_confirmed, ws_shift_status, ws_patterns
- ws_staff_settings (인원 프리셋)
- workschedule_delivery_v1: 최신 근무표 종합 이미지 공유 준비 상태. lastChangedAtMs, lastPreparedAtMs, lastSentAtMs, cliPatchCandidate(no_live_no_write)를 보관한다.
- hynixops_ops_manual_entries_v1: HynixOps에서 정리된 운영메뉴얼 후보. WorkSchedule 운영탭은 이 값과 메모 후보를 합산해 정리 항목으로 표시한다.
- hynixops_ops_manual_pending_memos_v1 / workschedule_hynix_ops_manual_memos_v1: 메모 후보 입력 경계. raw memo는 source/audit 용도이며 기본 화면에는 정리된 메뉴얼 본문만 표시한다.
- Firebase durable source: `/packhelper/ops_manual`. WorkSchedule 운영탭과 HynixOps 운영메뉴얼 탭은 이 경로를 읽기 전용으로 합산한다. 위 키들은 브라우저 보조 키이지 Firebase 원본 경로가 아니다.
- 위 키들은 브라우저 보조 상태이며 근무 데이터 원본은 Firebase `/workschedule_v2`다. 직원별 고정근무 시간은 `/workschedule_v2/fixed_schedules` 값을 기준으로 하며 코드 하드코딩 fallback을 두지 않는다.

## 근무표 종합 이미지 공유
- 스케줄 저장/상태/fixed schedule 갱신 write 성공 후 5분 idle이 지나면 최신 근무표 종합 이미지 공유 준비 상태가 된다.
- 마지막 이미지 공유 intent 큐잉 후 6시간이 지나면 최신 근무표 기준으로 주기 공유 due가 된다.
- 공유는 브라우저 Web Share API 또는 PNG 다운로드로만 연결한다. Kakao 자동 선택/자동 발송은 하지 않는다.
- 공유 전 gate 문구는 이미지 출력 후 목표 단체방을 직접 확인하라고 안내한다.
- 날씨/뉴스 보조정보가 비어 있으면 실제 외부 호출 없이 CLI 보정 후보만 만든다. 이미지 중심은 최신 근무표이고 보조정보는 누락 시 보정 대상 섹션이다.
- 백그라운드 자동 발송/실제 CLI 실행은 웹 코드가 수행하지 않는다. 웹 실행 중 pending/due 표시와 이미지 출력 gate까지만 제공한다.
